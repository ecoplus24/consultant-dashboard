# 규칙 기반 주식매매 백테스트 엔진

국내(KOSPI/KOSDAQ)와 해외(NYSE/NASDAQ) 주식 전략을 같은 코드로 검증한다.

---

## 먼저 읽을 것 — 100만원으로 1억은 왜 목표가 될 수 없나

100만원을 1억으로 만드는 건 **100배**다. 기간별로 필요한 연복리 수익률은 이렇다.

| 기간 | 필요 CAGR |
|-----|----------|
| 5년 | **151%** |
| 10년 | **58%** |
| 20년 | **26%** |
| 30년 | **16.5%** |

비교 기준:

- S&P500 장기 평균: 약 **연 7~10%**
- 워런 버핏 60년 평균: 약 **연 20%** (역사상 최상위권)
- 연 30% 이상 장기 지속: **사례가 거의 없다**

즉 5년·10년 안에 100배를 노리는 전략은 "좋은 전략"이 아니라 **레버리지와 집중투자로
분산을 포기한 도박**이다. 그 결과의 분포는 "1억"이 아니라 **대부분 0원, 극소수 대박**이다.

이 패키지는 그 사실을 숨기지 않는다. `goal` 명령이 몬테카를로로
**목표 달성 확률, 원금 손실 확률, 원금 90% 소실 확률**을 같이 뽑아 준다.

현실적인 경로는 두 가지뿐이다.

1. **기간을 늘린다** — 20~30년이면 필요 수익률이 달성 가능한 범위로 내려온다.
2. **추가납입을 한다** — 매월 넣는 돈이 초기 원금보다 훨씬 큰 영향을 준다.

```bash
# 원금만으로 10년에 1억  -> 연 58% 필요
python -m trading goal --market us --symbols SPY --target 100000000 --years 10

# 월 50만원씩 20년      -> 필요 수익률이 크게 내려간다
python -m trading goal --market us --symbols SPY --target 100000000 --years 20 --monthly 500000
```

```bash
python -m trading backtest \
    --market kr --symbols 005930,000660,035420 \
```

```bash
python -m trading goal --market us --symbols SPY,QQQ \
```

```python
from trading import quickstart
```

## 설계에서 타협하지 않은 것

백테스트가 실전보다 좋아 보이게 만드는 흔한 방법들을 구조적으로 막아 놨다.

| 흔한 함정 | 이 엔진의 처리 |
|---|---|
| **미래참조** — 당일 종가 신호를 당일 종가에 체결 | 신호는 t일 **종가**, 체결은 t+1일 **시가**. 전략은 잘린 뷰(`MarketView`)만 볼 수 있다 |
| **수수료·세금 무시** | 수수료 + 증권거래세(국내 매도 0.18%) + 슬리피지를 매 체결마다 부과 |
| **소수점 주식** — 100만원으로 30만원짜리를 0.3주 매수 | 기본이 정수 주식. 소액 계좌의 실제 제약을 그대로 반영 |
| **현금 초과 매수** | 가진 돈을 넘는 주문은 살 수 있는 만큼으로 축소. 레버리지는 아예 차단 |
| **거래정지·상장 전 매매** | `tradable` 마스크로 그 날 실제 데이터가 있는 종목만 주문 가능 |
| **생존편향** | 종목 리스트는 사용자가 준다. 지금 살아남은 종목만 넣으면 결과가 부풀려진다는 걸 인지하고 써야 한다 |

## 구조

```
trading/
├── data/          가격 수집·정규화 (KIS / KRX / yfinance / CSV / 합성)
├── strategies/    전략 — "목표 비중"만 결정한다
├── broker/        증권사 연동 (한국투자증권 KIS Open API)
├── risk.py        리스크 관리 — 손절·비중상한·서킷브레이커·변동성타겟
├── costs.py       수수료·세금·슬리피지
├── engine.py      이벤트 루프 백테스터
├── live.py        실전/모의 주문 실행 + 안전장치
├── metrics.py     CAGR·MDD·샤프·소르티노·칼마
├── report.py      성과표 + 몬테카를로 목표분석
└── cli.py         명령줄 진입점
```

전략과 리스크 관리를 분리한 게 핵심이다. 전략은 "무엇을 얼마나 들고 싶은지"만 말하고,
**얼마나 살지·언제 자를지는 리스크 계층이 강제한다.** 전략을 갈아끼워도 리스크 규칙은
항상 동일하게 걸린다.

## 전략

| 이름 | 설명 |
|---|---|
| `buyhold` | 동일비중 매수 후 보유. **벤치마크** |
| `macross` | 단기 이평선 > 장기 이평선인 종목 보유 (추세추종) |
| `momentum` | 듀얼 모멘텀 — 상대 강도 상위 N종목 중 절대수익률 > 0인 것만 |
| `rsi` | 장기 상승추세 종목의 단기 과매도 매수 (평균회귀) |

> 벤치마크를 **비용까지 감안해서** 못 이기는 전략은 만들 이유가 없다.
> `compare`는 리스크 오버레이를 적용한 결과와, 그냥 사서 들고 있었을 때를 같이 보여 준다.

## 리스크 프리셋

| 프리셋 | 종목당 최대 | 손절 | 추적손절 | 계좌 MDD 서킷 | 변동성 타겟 |
|---|---|---|---|---|---|
| `conservative` | 20% | -10% | -15% | -20% | 12% |
| `balanced` | 25% | -15% | -25% | -30% | 18% |
| `aggressive` | 50% | -25% | -35% | -45% | 없음 |
| `none` | 100% | 없음 | 없음 | 없음 | 없음 |

`none`은 비교용이다. 실제로 이걸로 운용하면 언젠가 계좌가 사라진다.

## 한국투자증권(KIS) 연동

계좌 개설 후 [KIS Open API 포털](https://apiportal.koreainvestment.com)에서
앱키/시크릿을 발급받아 환경변수로 넣는다.

```bash
export KIS_APP_KEY="..."
export KIS_APP_SECRET="..."
export KIS_ACCOUNT="12345678-01"   # 계좌번호 8자리-상품코드 2자리
export KIS_ENV="paper"             # paper(모의투자, 기본값) / live(실전)
```

### 명령

```bash
# 1. 잔고 조회 — 연결부터 확인한다
python -m trading account

# 2. 오늘 낼 주문 계산 (드라이런, 주문 안 나감)
python -m trading signal --symbols 005930,000660,035420 --strategy momentum

# 3. 모의투자로 실제 주문
python -m trading trade --symbols 005930,000660,035420 --execute

# 4. 실전 (--live + 콘솔에서 '실행' 타이핑 확인 필요)
python -m trading trade --symbols 005930,000660 --execute --live
```

`signal`은 **절대 주문하지 않는다.** `trade`도 `--execute` 없이는 계획만 보여 준다.

### 안전장치

실전 주문은 코드 버그 하나가 곧바로 돈이 된다. 그래서 여러 겹으로 막아 놨다.

| 장치 | 동작 |
|---|---|
| **모의투자 기본** | `KIS_ENV`를 지정하지 않으면 항상 모의투자 서버 |
| **드라이런 기본** | `--execute` 없이는 주문이 나가지 않는다 |
| **실전 이중확인** | 실전 계좌는 `confirm=True` + 콘솔에 `실행` 입력까지 있어야 통과 |
| **주문 금액 한도** | 1건 100만원 / 1회 총 500만원 (기본값, 조정 가능) |
| **지정가 강제** | 시장가는 기본 차단. 슬리피지를 통제할 수 없기 때문 |
| **호가단위 정렬** | KRX 호가단위에 맞춰 가격을 자른다. 안 맞으면 주문이 거부된다 |
| **예산 초과 차단** | 주문가능현금(미결제 제외) 범위 안에서만, 2% 여유를 남기고 산다 |
| **정규장 검사** | 평일 09:00~15:30 KST 밖에서는 실행 거부 |
| **동전주 제외** | 1,000원 미만 종목 매수 차단 |
| **첫 실패 시 중단** | 주문 하나가 거부되면 나머지를 밀어 넣지 않는다 |
| **호출 제한 준수** | 모의 초당 2건 / 실전 초당 20건 |

### 상태 저장

추적손절과 계좌 서킷브레이커는 **실행 사이에 기억이 필요하다.**
보유종목 고점과 계좌 고점을 `~/.cache/trading/live_state.json`에 저장한다.
이 파일을 지우면 손절 기준이 초기화되므로 주의할 것.

### 데이터 출처를 맞추는 것

`--market kis`를 쓰면 백테스트 일봉도 KIS에서 받는다.
**실전 주문에 쓰는 시세와 같은 출처**라 백테스트와 실전이 어긋나지 않는다.

```bash
python -m trading backtest --market kis --symbols 005930,000660 --strategy momentum
```

### 진행 순서 (건너뛰지 말 것)

1. `backtest` / `compare`로 전략이 **벤치마크를 비용까지 감안해 이기는지** 확인
2. `account`로 연결 확인
3. `signal`로 며칠간 주문 계획만 뽑아 보고, 나올 주문이 납득되는지 눈으로 검증
4. **모의투자로 최소 한 달** 굴려서 체결·거부·예외 상황을 다 겪어 본다
5. 그 다음에야 실전. 그것도 잃어도 되는 금액으로 시작한다

## 한계 (반드시 알고 쓸 것)

이 도구가 해주지 **않는** 것들이다.

1. **백테스트 성과는 미래를 보장하지 않는다.** 과거에 통했다는 것과 앞으로 통한다는 건 다르다.
2. **생존편향**을 자동으로 걸러주지 않는다. 지금 우량한 종목만 골라 넣으면 결과가 부풀려진다.
   상장폐지된 종목까지 포함한 리스트로 검증해야 정직한 숫자가 나온다.
3. **과최적화(오버피팅)** 를 막아주지 않는다. 파라미터를 이리저리 바꿔서 제일 좋은 걸
   고르면, 그건 전략이 아니라 과거 데이터에 맞춘 곡선이다.
   기간을 나눠서(in-sample / out-of-sample) 검증해라.
4. **체결 가정은 낙관적이다.** 시가 체결을 가정하지만 상한가·하한가, 거래량 부족,
   호가 공백에서는 그 가격에 못 산다.
5. **KIS 연동은 실제 서버로 검증되지 않았다.** 응답 해석과 안전장치는 가짜 응답으로
   테스트했지만, 실제 계좌로 주문해 본 적은 없다. TR ID와 응답 필드는 증권사가
   개정할 수 있으므로 **반드시 모의투자로 먼저 확인**해라.
   TR ID는 `KISConfig(tr_overrides={...})`로 코드 수정 없이 바꿀 수 있다.
6. **미체결 관리가 없다.** 지정가 주문이 체결되지 않고 남아 있는 경우를 추적하지 않는다.
   장 마감 시 미체결분은 자동 취소되지만, 그 사이 목표 비중과 실제 보유가 어긋난다.
7. **공휴일 달력이 없다.** 정규장 시간만 검사하고 휴장일은 판별하지 않는다.
